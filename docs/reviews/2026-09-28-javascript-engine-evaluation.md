# JavaScript engine feasibility evaluation

Date: 2026-09-28. Baseline: `d6da15425d0aa4354641d643e28cbe35ca9e17db`.

## Disposition and scope

**Outcome B: no engine selected. No engine ADR is created.** Phase 3 remains active. [RFC 0001](../../spec/rfcs/0001-javascript-execution-binding.md) remains proposed, internally reviewed, neither accepted nor implemented. The existing declarative runtime, its dependencies, and its 34-case corpus are unchanged.

QuickJS-NG with rquickjs was the strongest first *experiment*: it exposes single-job pumping, direct Promise state, interruption and a non-executing Proxy predicate in a comparatively small embeddable API. The [isolated spike](../../experiments/javascript-engine-spike/README.md) demonstrates those primitives, but also reproduces a material gap in the proposed invocation boundary: a pending Promise reaction, including an internal `await` continuation, can survive a successful call and execute during a later one. The reviewed public API supplies no reaction revocation/ownership mechanism. Successful primitive tests are not a finding of RFC compatibility.

Boa offers a potentially useful investigation path through callback records and host hooks. V8 and JavaScriptCore have capable native engines, but the reviewed embedding surfaces do not establish all the required scheduling and inspection guarantees. None has enough combined evidence here for a selection. An engine decision would belong only to the Rust reference implementation, never to the source format or portable specification.

This is a feasibility review, not a performance comparison or security audit. No manifest loading, module loader, operation dispatcher, services, JavaScript conformance corpus or production engine abstraction was added. Node.js and Deno are host environments with additional APIs and scheduling, not substitutes for evaluating their underlying engine's embedding primitives.

## Modules, language and exact source

All four engine families implement ES modules and broad modern ECMAScript. Bellard currently advertises ES2025; NG documents a broad modern feature set; Boa still reports incomplete overall Test262 coverage. None was verified against the exact RFC ES2023 subset here. Later features must not leak into portable semantics simply because an engine accepts them.

| Candidate | Usable mechanism | Remaining RFC work |
| --- | --- | --- |
| QuickJS-NG | `Module::declare`/compile-only native evaluation can separate compilation from evaluation; resolver/loader hooks and native `JS_ResolveModule` permit explicit host-controlled dependencies. rquickjs loader support exists behind a feature, not enabled in the spike. | No public AST in reviewed C API. A real syntax preflight must reject dynamic import, `import.meta`, TLA and disallowed export forms, including unreachable occurrences. A resolver callback alone cannot do that. No parser or loader selected/tested. |
| Boa | Public parser/AST and Module parse/link/evaluate stages; custom ModuleLoader can prevent ambient resolution. | Inspect AST against the exact profile and test all entry/export/async-initialization rules. Default file loader is not the intended package resolver. |
| V8 | Module compilation/instantiation with embedder resolver and dynamic-import/import-meta callbacks. | Do not mistake rejecting callback execution for rejecting forbidden syntax anywhere in the graph. Independent preflight or adequately exposed parse metadata is still required. |
| JSC | Native internal module system; reviewed fork exposes module extension APIs. | Public Apple C API alone does not establish equivalent custom graph/preflight control. Fork ABI and parser access would need separate proof. |

For every candidate, the embedding layer must first capture immutable exact text, enforce bytes/count/depth, resolve only allowed local package paths, reject bare/remote/package-manager names, build the complete graph and reject cycles before evaluation. No engine should be trusted to infer DAG-only policy. Engine compilation and preflight must consume the same snapshot. The graph policy is feasible host work; exact parse/feature agreement and initialization/export handling remain untested. No runtime parser, module loading, module fixtures or package access was implemented in this unit.

## Promise boundary and invocation ownership

RFC 0001 requires synchronous values or intrinsic Promises, host-selected terminal outcomes, FIFO jobs scoped to one invocation, no extra observation turn, and revocation of old reactions even if they have not been enqueued yet. Serializing API calls alone is insufficient.

| Candidate | Direct observation / scheduling | Boundary assessment |
| --- | --- | --- |
| QuickJS-NG / rquickjs | `Promise::state`/`result` read engine state without `.then`; `execute_pending_job` executes one runtime job. Native job queue is FIFO. Host-created resolvers can be called by the owner thread. | Local evidence proves terminal observation before the next queued job and that an empty queue does not block host cancellation/deadline checks. **No public discard/tag/revoke primitive for retained reactions.** Later pumping executes old work. |
| Boa | `JsPromise::state`, custom `JobExecutor`, callback records with host-defined payload through `make_job_callback`/`call_job_callback`. | Source shows `await` reaches `perform_promise_then`, which creates these callback records. Promising for registration-time ownership, but not tested. Hook documentation requires calling the recorded callback; treating it as a veto would need a justified embedding extension. Suppressing a callback may still resolve/reject children or enqueue more jobs. No compatibility claim. |
| V8 / rusty_v8 | Intrinsic Promise state/result, explicit microtask policy, queue association and Promise hooks. | Reviewed `perform_checkpoint` runs a checkpoint, not one job. No demonstrated way to stop at the RFC terminal boundary and revoke pending reactions while preserving a healthy realm. Hooks or execution termination cannot simply be assumed equivalent to discard. |
| JSC / rust_jsc | Public API can create deferred Promises; engine internally manages microtasks. | Public portable Rust path to non-turn Promise inspection, FIFO one-job pumping and retained-reaction revocation not established. Fork/internal APIs may help, but require evidence. |

The QuickJS-NG repro consists of a synthetic call A registering `pending.then(oldCallback)` and returning `1` with no jobs pending. Synthetic call B invokes the retained resolver. Pumping once runs `oldCallback`. A second test replaces `Promise.prototype.then`; an `await pending` continuation still runs after later resolution and never calls that wrapper. Thus source wrappers cannot cover all reaction registration. The spike deliberately observes the forbidden behavior; its passing assertions document the blocker.

The pinned `quickjs.c` stores handlers in `perform_promise_then`, queues reactions on fulfillment, and calls the handler directly in `promise_reaction_job`. `JS_SetPromiseHook` has a void observational callback, not a veto/ownership token. It does not provide the missing reaction lifecycle contract. Dropping a queue would not revoke unqueued reactions. Draining after success executes forbidden source work. Disposing every successfully used instance would lose the RFC's reusable state. Neither is an acceptable silent workaround.

A future owner scheduler would also have to tag host completions, check cancellation/deadlines while waiting on a never-settling Promise, and discard completions for terminal invocations without calling source again. The spike only calls a local Promise resolver, with no services, concurrency scheduler or timers. It demonstrates the needed polling primitive, not this complete ownership design.

## CPU interruption, isolation and resources

QuickJS-NG's runtime interrupt handler is exposed by rquickjs. The local loop test triggers on the fifth polling callback, returns an exception and runs neither a source `catch` body nor code after the loop. An already queued callback also never runs when the context and runtime are dropped without pumping. A separately prepared catastrophic-backtracking regexp reaches the hook and returns an error. Native `lre_check_timeout` connects regexp polling to the runtime handler. This proves two workloads, not bounded latency in every native builtin. Host cancellation/deadline state can be consulted in this callback; no hard real-time preemption is claimed.

The embedding layer must record the host terminal reason itself, reject later work, release held values, and discard the interrupted instance rather than treating an arbitrary exception string as cancellation or reusing partially mutated state. Dropping these isolated runtimes supplies no background JS thread to continue their jobs. The test's host callback counter remains zero after disposal; it does not implement the production lifecycle.

| Candidate | Isolation and disposal route | Limits and gaps |
| --- | --- | --- |
| QuickJS-NG | Distinct `JSRuntime`s give distinct heaps/job queues; contexts within one runtime can share objects, so context count alone is not isolation. Two runtimes locally retain independent mutable globals/intrinsics; state persists across serialized calls. | `JS_SetMemoryLimit`, allocator hooks (`JS_NewRuntime2`), max stack and interrupt handler; wrappers expose limits. Spike configures 16 MiB engine allocation and 256 KiB stack limits, but does not test exhaustion. No exact process/portable heap quota, no public independent job-count quota; job allocations consume engine memory. Host data/buffers and source/graph bounds are separate. |
| Boa | Separate contexts/realms have distinct globals, but host-held `JsObject`s can be shared; embedder must prohibit this and own executors/handles. GC disposal is not automatically immediate memory reclamation. | Public loop iteration, stack and recursion limits. Adequate cancellation checkpoints across arbitrary CPU/native regexp work and per-instance memory accounting not demonstrated. Rust-native allocation is not a per-instance quota. |
| V8 | Separate isolates provide a stronger heap boundary than contexts; embedder must avoid cross-instance handles and own queue lifetimes. `terminate_execution`/interrupt APIs exposed. | Heap/stack constraints and near-heap callbacks exist; OOM/fatal paths and interruption recovery need testing. No exact process quota. Dropping isolate/handles after termination is a candidate disposal route, untested here. |
| JSC | Context groups isolate object-sharing/VM domains; globals in a shared group are not equivalent to independent heaps. | Private `JSContextGroupSetExecutionTimeLimit` supports a termination callback, configured before execution. This is not established as a portable public Apple/Rust API. Public per-instance allocation/stack/job controls insufficiently evidenced here. |

For every route, source/module byte limits, structural-copy budgets and host completion admission limits remain embedding responsibilities. Preserve Phase 2's structural and implementation-specific resource guarantees. No inference of portable memory quotas or perfect denial-of-service protection follows from these APIs.

| Candidate | Compilation control | Global surface |
| --- | --- | --- |
| QuickJS-NG | No per-context string-compilation denial callback found in the reviewed public API. | Boa | `HostHooks::ensure_can_compile_strings` is called by eval and the shared dynamic function construction path (including async/generator flags). | V8 | Rust binding exposes engine policy for code generation from strings; aliases should reach engine compilation checks, but all RFC routes and exact EvalError behavior need tests. | A bare context does not imply DOM/Node, but clocks/randomness/locale, binary and implementation diagnostics still need removal or replacement. | JSC | `JSGlobalContextSetEvalEnabled` in a **private** header documents eval/Function restriction. The local QuickJS-NG bootstrap privately captures the ordinary, async, generator and async-generator constructors before source runs; replaces their prototype `constructor` properties with a non-writable/non-configurable EvalError stub; and similarly locks global eval/Function. The stub's prototype is set to the original Function prototype. Twelve probes cover direct/indirect/global eval, Function call/new, all four constructor paths, prototype lookup, Reflect.construct and Object-constructor chaining. Attempts to overwrite the global/prototype slots do not restore compilation; all twelve throw EvalError and the generated body runs zero times.

This supports the *specific bootstrap strategy*, not a complete hardened realm. Constructor recovery through every intrinsic path, replacement-global semantics, engine upgrades, extra extensions and Error/locale methods still require a dedicated audit and tests. An engine-level hook is preferable where available. There is no claim that deleting two globals is sufficient or that ordinary source mutation of unrelated objects has been exhaustively tested.

The ambient test checks 13 absent names: process, require, Buffer, fetch, XMLHttpRequest, window, document, navigator, setTimeout, Worker, console, std and os. The engine's separately provided standard-library modules were not injected. This proves only those absences in this configuration. Exact allowed globals, nested methods, clock/timezone/randomness removal and suppression of source-visible engine stack details remain missing evidence for every candidate. No host object or service was exposed except the test-only interruption counter callback.

## Non-executing structural transfer and diagnostics

Inspection must first establish safe engine classes without coercion, reject proxies/exotics, then inspect descriptors. Calling source `JSON.stringify`, `toJSON`, iterators, getters, coercion or mutable Object helper functions would violate the rule. A generic property getter is not a descriptor reader.

| Requirement | QuickJS-NG / rquickjs evidence | Other candidate assessment |
| --- | --- | --- |
| Primitives, object identity | Tagged values and Rust `Value` inspection; integer result tested. Preserve finite-number/type checks in a bounded future copier. | Boa typed values and V8 type predicates offer equivalent starting points. JSC public type tests exist; conversion APIs may coerce. |
| Own keys/descriptors/accessors | Raw `JS_GetOwnPropertyNames` and `JS_GetOwnProperty`; ordinary object's accessor descriptor identified with zero getter calls locally. Convenience `props`/get APIs are unsuitable for non-executing reads. | Boa exposes internal property maps/descriptors and object types; V8 exposes own descriptors. Public JSC property getters/names alone are not sufficient proof of getter/trap-free transfer. |
| Prototype/exotics | After safe class check, compare prototype identity with privately retained intrinsic prototype/null. Tested on one plain object only. `JS_GetClassID` and native predicates can reject classes; comprehensive class handling not implemented. | Boa `is_ordinary`/native downcasts and V8 predicates support guards. Custom prototypes and host/native wrappers still need exact policy in every engine. |
| Holes, symbols, cycles | Enumerate own descriptors with string/symbol flags, distinguish absent index from undefined and track live object identity with depth/node/byte bounds. These API-based paths were inspected, not implemented/tested here. Default string key iteration alone would miss symbols. | Boa/V8 have key/type/identity APIs for this approach. JSC public-only path remains unproven. No candidate has a completed RFC copier. |
| Promises, buffers, typed arrays, native handles | Promise type/state, ArrayBuffer/typed-array/class predicates; reject rather than coercing. Only Promise identification exercised; remaining types desk-assessed. | Boa native object types and V8 predicates expose distinctions. Bindings/host registration must prevent unrecognized handles being treated as records. |
| **Proxy** | Public `JS_IsProxy` is a non-executing class predicate. Test observes zero traps, then deliberately enumerates the Proxy and observes one `ownKeys` trap. **Guard before keys, descriptors or prototype**, including revoked proxies. Revoked/nested combinations not tested. | Boa can downcast/check JsProxy before internal operations; V8 exposes `is_proxy`. Both require local tests. JSC's `JSObjectGetProxyTarget` is private; public-only non-executing rejection not established. Bellard header lacks NG predicate; require class-guard evidence or full Proxy prevention, not a trapping inspection. |

A safe class check must reject *all* unsupported engine/host exotic objects, not just a Proxy with an ordinary target. Preventing creation of Proxy could be a separate profile-hardening strategy because RFC globals exclude it, but would require proof that no constructor/host path can introduce one. The spike intentionally keeps Proxy enabled to test the boundary and does not rely on that assumption. A trap that throws is still execution and cannot count as non-executing rejection.

QuickJS-NG returns engine exceptions through its exception sentinel/value API; the spike discards rejected Promise diagnostics without formatting them. Boa separates native/opaque errors; V8 provides TryCatch/termination state; JSC uses exception output values. These allow host-side classification in principle. The host must select cancellation/timeout/resource outcomes from its own state and otherwise emit fixed sanitized SOURCE_ERROR data, never stringify arbitrary thrown values, read their stack/message getters, or publish engine formatting/paths. Source-visible Error.stack and other diagnostic extensions also need profile hardening; sanitizing the output alone is not the full RFC rule. No portable exact exception strings are assumed.

## RFC feedback and smallest follow-up

1. **F1 — pending reaction ownership/revocation (material; engine API and RFC feasibility).** QuickJS-NG public APIs do not establish the RFC boundary while retaining healthy instance state. `.then` interception is bypassed by await. V8 checkpoint control and JSC public API do not supply a demonstrated alternative here. This is not a proof of impossibility across all engines, nor permission to weaken the RFC. Resolve this issue before production execution.
2. **F2 — exact deterministic realm and non-executing copy (missing evidence).** The local constructor/accessor/Proxy probes support useful primitives but not complete hardening, ES2023 preflight or safe handling of all exotics. Record those as acceptance prerequisites, not production-ready features. Engines/bindings lacking safe Proxy identification need a demonstrated prevention strategy or API change.
3. **F3 — portable control versus engine/binding extensions (binding/platform evidence).** JSC private/fork controls, possible engine patches for revocation, and Boa hook semantics have maintenance and portability costs. Any proposal that changes terminal timing/reuse/reaction behavior must be independently justified through the RFC process. Platform claims need named target builds and execution, not desktop inference.

The smallest next unit is **a focused Boa callback/job ownership experiment and RFC F1 design review**, not production execution: stamp reaction registration in `make_job_callback`, trace both `.then` and `await` across two synthetic invocations, and determine whether queued and unqueued old work can be suppressed without executing callbacks, settling observable child work, or violating hook contracts. Include a never-settling returned Promise and a terminal Promise that queues later work. If public hooks cannot faithfully implement this, document the minimum engine extension or explicitly reconsider the RFC ownership model.
